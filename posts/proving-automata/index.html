Fun(ctions) with Automata in Lean

September 25, 2026 #formal methods #theory of computation

I’m assuming at least some familiarity with proofs / logic / discrete mathematics for computer science in this post. Also, it might be a little long so consider this your attention span warning!

1.Introduction¶

I took my university’s undergraduate theory of computation course last quarter, and I really enjoyed it because I found a lot of the topics really cool. It’s also neat that the class counts towards both my majors, Computer Science, and Philosophy.1

This post is about one of the assignments which involved working with an arbitrarily defined ‘Very Simple Automaton’ (VSA) and then proving its limitations in comparison to the Deterministic Finite Automaton (DFA).

2.Regular Languages¶

All of the stuff talked about in this post really revolves around the idea of a ‘regular language’. I hope this bit serves as a good refresher.

You may be familiar with RegEx or Regular Expressions, these are a way to define regular languages recursively.

DFAs were conceived as automatons that could recognise regular languages.

They’re subject to the pumping lemma.

Here’s how Mathlib/Computability/DFA.lean defines and states the pumping lemma in Lean.

theorem pumping_lemma [Fintype σ] {x : List α} (hx : x ∈ M.accepts)
    (hlen : Fintype.card σ ≤ List.length x) :
    ∃ a b c,
      x = a ++ b ++ c ∧
        a.length + b.length ≤ Fintype.card σ ∧ b ≠ [] ∧ {a} * {b}∗ * {c} ≤ M.accepts := by
  obtain ⟨_, a, b, c, hx, hlen, hnil, rfl, hb, hc⟩ := M.evalFrom_split (s := M.start) hlen rfl
  use a, b, c, hx, hlen, hnil
  intro y hy
  rw [Language.mem_mul] at hy
  rcases hy with ⟨ab, hab, c', hc', rfl⟩
  rw [Language.mem_mul] at hab
  rcases hab with ⟨a', ha', b', hb', rfl⟩
  rw [Set.mem_singleton_iff] at ha' hc'
  subst ha' hc'
  have h := M.evalFrom_of_pow hb hb'
  rwa [mem_accepts, eval, evalFrom_of_append, evalFrom_of_append, h, hc]

2.1.DFAs¶

First, let’s refresh our minds on the formal definition of a DFA how people traditionally write it. According to Sipser2,

“ a finite automaton [(DFA)] is a 5-tuple (𝑄,Σ,𝛿,𝑞0,𝐹), where

  1. 𝑄 is a finite set called the states,

  2. Σ is a finite set called the alphabet,

  3. 𝛿:𝑄×Σ→𝑄 is the transition function,

  4. 𝑞0∈𝑄 is the start state, and

  5. 𝐹⊆𝑄 is the set of accept states.

”

2.2.VSAs¶

Here’s how I defined the VSA per the natural-language description, slightly modified after feedback :

“A Very Simple Automaton (VSA) is a 5-tuple 𝑇=(𝑄,Σ,𝛿,𝑠,𝐹) of the following:

  1. 𝑄 is the set of states of the VSA {𝑞0,𝑞1,…,𝑞𝑛}

  2. Σ is the alphabet of symbols that make up the strings over which the VSA performs computations

  3. 𝛿 is the function making state transitions, 𝛿:𝑄×Σ→𝑄 such that there are two possible cases,

    𝛿 : { 𝛿 ( 𝑞 𝑖 , 𝑤 ) = 𝑞 𝑗 : 0 ≤ 𝑗 ≤ 𝑛 ∈ 𝑄 | VSA consumes sym 𝛿 ( 𝑞 𝑖 , 𝑤 ) = 𝑞 𝑖 | VSA changes state

  4. 𝑠 is the start state, 𝑠∈𝑄

  5. 𝐹 is the set of all accept states, 𝐹⊆𝑄

”

3.Greater Formalism in Lean¶

Here’s the formal definition of a DFA in Lean, from Mathlib:

universe u v

open scoped Computability

/-- A DFA is a set of states (`σ`), a transition function from state to state labelled by the
  alphabet (`step`), a starting state (`start`) and a set of acceptance states (`accept`). -/
structure DFA (α : Type u) (σ : Type v) where
  /-- A transition function from state to state labelled by the alphabet. -/
  step : σ → α → σ
  /-- Starting state. -/
  start : σ
  /-- Set of acceptance states. -/
  accept : Set σ
